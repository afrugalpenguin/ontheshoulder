# Decisions

One line per decision, newest at the bottom. Date, decision, reason. Reversible unless marked.

- 2026-10-11: TypeScript monorepo (pnpm) with a Python sidecar only for Garmin. One language for the app; the only maintained Garmin client is Python.
- 2026-10-11: SQLite with Drizzle, WAL mode. Single user, single machine, backup is a file.
- 2026-10-11: Garmin via `python-garminconnect` 0.3.x, treated as a best-effort feed. Garmin offers no personal API; the March 2026 auth change killed `garth`, so isolate the risk in its own process and fail closed.
- 2026-10-11: No service worker or PWA install in v1. LAN http is not a secure context; bookmark is enough.
- 2026-10-11: Progression rules stored as JSON on the block, interpreted by a pure engine with table tests. Tuning without deploying.
- 2026-10-11: The race date is entered at setup and flagged unconfirmed until the event is chosen.
- 2026-10-11: v0.2. No injury gating anywhere; the app records and shows, the user judges. Progression is calendar-driven and editable.
- 2026-10-11: Runs are recorded on the watch. The app timer covers vest walks and strength rest only.
- 2026-10-11: Sunday sessions are optional by rule: done is a bonus, missed never fails the week. Compliance is weekday-based.
- 2026-10-11: Main lifts on linear 5x5 (+2.5kg per session, hold once, deload 10 per cent on second fail); accessories on double progression. All loads snapped to kit the user owns.
- 2026-10-11: Equipment is configured per user (plates, bar, dumbbells, kettlebells, vest), each possibly none. Substitutes offered when kit is missing.
- 2026-10-11: Habit prompts (protein shake seeded) shown on Today until ticked or the cut-off time; text and times editable.
- 2026-10-11: Repo is public-ready from the start: MIT, no personal data in the tree, database and backups outside the repo. Rejected committing the database or a text dump for the same reason.
- 2026-10-11: Garmin sidecar demoted to optional and last.
- 2026-10-11: v0.2.1. Midweek run: the week run_sec would hit 300 is the first 25 min continuous run (week 7), not a final run-walk week. Long run grows by repeats (+3 per week to 30) with 120/60 blocks fixed. Race specifics removed from docs; only the event shape is described.
- 2026-10-11: pnpm pinned to 10.34.6 through `packageManager` and run via corepack. The corepack bundled with Node 22 and 24 could not launch pnpm 12; revisit when it can.
- 2026-10-11: TypeScript held at 6.0.x. typescript-eslint 8 does not accept TypeScript 7 yet.
- 2026-10-11: `packages/shared` compiles to `dist` and the root `dev`, `test` and `typecheck` scripts build it first. Keeps the api build rooted at `apps/api/src` and works once shared holds runtime code.
- 2026-10-11: `services/garmin` is a plain Python project, not a pnpm workspace member. It has no Node code.
- 2026-10-11: One `.env` in the repo root, read by the api and by the web dev proxy, so the port cannot drift. Names: `OTS_HOST`, `OTS_PORT`, `OTS_LOG_LEVEL`.
- 2026-10-11: api routes are unprefixed for now (`/health`); the web dev proxy strips `/api`. Stage 10 moves routes under `/api`.
- 2026-10-11: Sidecar declares `requires-python >=3.12` and CI runs 3.12. Lets a newer local interpreter work until 3.12 is installed.
- 2026-10-11: Prettier ignores `docs/`. Hand-written tables stay as written.
- 2026-10-11: v0.2.2. Race generalised to Event with priority A/B/C and status. One A event drives the countdown; B and C events are milestones and can end blocks. Setup asks for the A event only.
- 2026-10-11: Stage 3. TypeBox schemas live in `packages/shared` and both sides take their types from them with `Static`; no separate code generation step.
- 2026-10-11: Stage 3. Session templates carry a stable `key` so rules, fixtures and the starter template can refer to them by name. Starter template rows are matched on natural keys, so applying twice inserts nothing and never overwrites edits.
- 2026-10-11: Stage 3. At most one A event is enforced on write (409); zero A events is allowed and simply leaves setup incomplete.
- 2026-10-11: Stage 3. `PUT /checkins/:date` merges, and sleep and energy are nullable, so a habit tick can be saved before the morning check-in. Dismissed prompts are stored on the check-in row, not on the phone.
- 2026-10-11: Stage 3. The api migrates the database on start as well as through `db:migrate`. One fewer manual step for a self-hosted install.
- 2026-10-11: Stage 3. Generated migrations are lowercased by `db:lowercase` before they are first applied, to keep SQL keywords lowercase.
- 2026-10-11: Stage 3. The starter template block starts on the Monday of the week it is applied unless a start date is sent. The two fixed-load slots keep their guidance in notes because the template holds no loads.
- 2026-10-11: Stage 3. `plate` equipment loads are the single plate sizes owned.
- 2026-10-11: Stage 4. Progression reads the previous week's targets for the same template; with no previous week it starts from the rule's start values. Edits therefore carry forward.
- 2026-10-11: Stage 4. A continuous run is stored as one repeat with no walk block. `duration_min` is always the whole session including warm-up and cool-down.
- 2026-10-11: Stage 4. Treadmill days are counted from done sessions in the rule's slot on its weekdays, not from the habit tick, because the engine never reads check-ins.
- 2026-10-11: Stage 4. Regeneration keeps any session that is edited, linked, done or skipped; a kept session the user moved to another day stands in for its fixture so no duplicate is created.
- 2026-10-11: Stage 4. Scheduler is a one-minute `setInterval` with the handled week persisted in `app_state`, using the PC's local time. Settings live on the athlete row (`plan_weekday`, `plan_time`).
- 2026-10-11: Stage 4. `suggestLoad` takes the slot's session history (most recent first) because the deload rule needs two sessions. A null increment means "next load the kit can make"; an increment that cannot be made holds.
- 2026-10-11: Stage 4. A week no block covers is generated from fixtures alone, and the reasoning says so.
- 2026-10-11: Stage 5. React Router 7, because version 8 needs React 19 and the stack is on React 18.
- 2026-10-11: Stage 5. "Today" and prompt cut-off times come from the phone's clock; the wizard sends that week's Monday as the block start so the first generated week is the one the user is in.
- 2026-10-11: Stage 5. The compliance line counts "key sessions" and "treadmill mornings" generically from the block's rules, so it reads the same for any template.
- 2026-10-11: Stage 5. Session kind "icons" are short text badges, always next to the session name. No icon font or image assets.
- 2026-10-11: Stage 5. Building the week by hand in the wizard creates one simple session template per row (kind, name, minutes). Richer templates are edited through the api for now.
- 2026-10-11: Stage 5. Start on a walk routes to a `/timer/:id` placeholder until stage 6; Start on a run is disabled with "Recorded on your watch".
- 2026-10-11: Stage 5. Lighthouse was run headless on the PC for the PR, not added to CI. The Playwright flow is in CI.
- 2026-10-11: Stage 6. Timer position is computed from elapsed time on `performance.now`; a tick that covers more than 1.5 seconds is treated as a resume and issues only the latest transition cue.
- 2026-10-11: Stage 6. Skipped time is kept out of the total. The saved activity records planned and actual seconds per phase under `detail.timer`.
- 2026-10-11: Stage 6. Sessions with run and walk blocks get warm-up, repeats and cool-down; every other session is one stretch with a half-way cue. Start is offered on walks only, so the interval form is reachable by URL but not from a run card.
- 2026-10-11: Stage 6. `RestTimer` restarts when its `resetKey` prop changes; a skip calls `onDone` without the finish tone.
- 2026-10-11: Stage 6. End-to-end flows run against the built bundle through `vite preview`, with the same `/api` proxy as dev.
- 2026-10-11: Stage 7. A set records `exercise_id` only when a substitute was done. A substitute keeps its own history and starting load; making a swap permanent labels the slot's earlier sets with the old exercise first.
- 2026-10-11: Stage 7. A substitute that is not a barbell lift steps to the next load the kit can make, whatever the slot's increment was.
- 2026-10-11: Stage 7. Tapping a logged set undoes it. Holding a set row, the context menu, or the Adjust button all open the same editor, so nothing depends on a long press working.
- 2026-10-11: Stage 7. The session is held in memory until Finish; a partial session is whatever has been logged when Finish is pressed.
- 2026-10-11: Stage 7. Strength sessions are dated today and linked to today's planned session for that day if there is one, else the first open one this week.
- 2026-10-11: Stage 7. The starter template's library gained twelve same-pattern alternatives (dumbbell, kettlebell and bodyweight) so substitution has something to offer. A carry has no bodyweight alternative, so that slot can say none available.
- 2026-10-11: Stage 9. Charts use uPlot: small, canvas based, and loaded only with the Trends tab. Recharts was the alternative and is several times the size.
- 2026-10-11: Stage 9. Trends are computed in a thin pure TypeScript layer over plain row queries, not in SQL, so the arithmetic is unit tested on fixed data.
- 2026-10-11: Stage 9. Run and vest-walk bars are stacked in minutes to share an axis; text reports vest walks in hours. Means ignore days with no entry instead of counting them as zero.
- 2026-10-11: Stage 9. "Main lifts" are slots on the linear rule; the chart shows the two with the most history. A substitute set counts under the exercise actually done.
- 2026-10-11: Stage 9. The review card compares the current ISO week with the one before using fixed sentences and no judgement words.
- 2026-10-11: Stage 9. Request bodies are no longer type-coerced (only query strings and path parameters are), because coercion turned a real 0 into null in nullable fields.
- 2026-10-11: Stage 10. Every api route is under `/api` in every mode, dev included; the dev proxy no longer rewrites paths. `/health` is now `/api/health`.
- 2026-10-11: Stage 10. The LAN guard allows loopback and RFC 1918 addresses plus their IPv6 counterparts (`::1`, unique local, link-local). Carrier-grade NAT and 169.254 addresses are refused. `OTS_LAN_GUARD` must be exactly `true` or `false`; anything else stops the api from starting so a typo cannot switch the guard off.
- 2026-10-11: Stage 10. Backups run on start and when the clock passes 02:00 (checked each minute); a start after 02:00 counts as that night's. Only files named `ots-YYYYMMDD-HHmm.db` are pruned.
- 2026-10-11: Stage 10. The Garmin sync task is only registered with `-IncludeGarmin`, because the sidecar was not built. All three PowerShell scripts support `-WhatIf` or `-Force` so they can be checked without changing the PC.
- 2026-10-11: Stage 10. Reordering blocks lays them back to back from the earliest start, each keeping its length. Creating or editing a block that overlaps another is refused with 409.
- 2026-10-11: Stage 10. A dry run uses the same engine as generation with nothing written, and accepts unsaved rules so the editor can try them first.
- 2026-10-11: Stage 10. The rolling log file goes in `<data folder>/logs` unless `OTS_LOG_DIR` is set.
- 2026-10-11: Stage 10. The personal-data check skips `LICENSE`, where the copyright holder's name belongs, and can take its terms from a CI secret (`OTS_PERSONAL_TERMS`) as well as the local `.personal-terms` file.
- 2026-10-11: Stage 10. A systemd user unit is provided for Linux alongside the Windows scripts.
- 2026-10-11: Stage 12. Colour tokens are accent, success and warning; warning doubles as the error and danger colour, and skipped sessions use it with a dashed border. Raw lengths survive only in the token definitions and the 900px breakpoint, because a media query cannot read a custom property.
- 2026-10-11: Stage 12. The next-day prompt is one editable line on a `kit_ready` habit, with `{session}` replaced by what is planned, instead of a line per session kind. The habit is seeded by the starter template; a database set up before this stage has no such habit and gets the same default wording until one is added in Settings.
- 2026-10-11: Stage 12. Streaks are worked out in the browser from existing endpoints. A treadmill morning is a weekday with a morning (am) session done. The mornings streak looks back four weeks and shows a plus sign when it reaches that far.
- 2026-10-11: Stage 12. Start on a vest walk opens the timer already running, so the walk is Start then Finish. The log sheet is minutes, RPE and a note for every kind; the vest weight is taken from the plan.
- 2026-10-11: Stage 12. Every screen but Week loads on first use, and the web build writes gzip and brotli copies that the api serves as they are. This took Lighthouse mobile performance on Week from 64 to 98.
- 2026-10-11: Stage 12. Week draws once all of its first-screen data has arrived, so nothing shifts as it loads.
- 2026-10-11: Stage 13. The run mode is a `runs` section in the block rules: `{ "mode": "timebox" }` or `{ "mode": "runwalk" }`. The starter keeps the `midweek_run` and `long_run` ladder settings beside it, unused in timebox mode, so switching back is a one-word edit.
- 2026-10-11: Stage 13. A block whose rules have no `runs` section keeps the run-walk ladder, so blocks saved before this stage plan exactly as they did. Only a newly applied starter template gets time boxes.
- 2026-10-11: Stage 13. A time box is `min_min` and `max_min` on the template structure, passed through as the same two fields on the session targets. Switching to runwalk starts the ladder at its first week, because a time box has no run block to progress from.
- 2026-10-11: Stage 13. The run log sheet is minutes, RPE and an optional "how was it" (good, fine, grim), saved as `detail.feel`. It has no notes field. Week's header shows run minutes from the existing weekly trends endpoint.
- 2026-10-11: Stage 13. This stage departs from SPEC 6.3 rules 1 and 2 (run-walk as the Block 1 default) and from the run fields listed in SPEC 5.2 and 5.3. The spec text is left as it is; `docs/PLAN.md` describes the new default.
- 2026-10-11: Stage 14. Schema change, as the brief allows: `set_log.warmup` (default false) and `programme_slot.warmups_enabled` (default true), in migration `0003_warmups`. Warm-up sets are left out of progression, of "session complete", and of the working weights in trends.
- 2026-10-11: Stage 14. The "warm-ups on" default in Settings is one switch that sets `warmups_enabled` on every linear slot, because the brief rules out any other schema change and the athlete has no column for it.
- 2026-10-11: Stage 14. The warm-up ramp is the bar twice, then 40 and 60 per cent of the working load snapped to the nearest makeable load. A step that lands on the bar or does not climb is dropped. Warm-up circles do not start the rest timer.
- 2026-10-11: Stage 14. A set keeps the load it was first logged at; changing the load with the pencil applies to the sets still to do, for this session only. Taking reps off a logged set does not restart the rest.
- 2026-10-11: Stage 14. Finish goes back to the Strength tab with a toast; "Add RPE" on the toast opens a 1 to 10 row that saves to the activity. The v1 "saved" summary page is gone, since each linear slot now shows its next load in the session and the day card shows it afterwards.
- 2026-10-11: Stage 14. The arrow on a day card compares the next load with the last session's: up, down, or none when it holds. Ticks, crosses, arrows and the pencil are small inline drawings with a text label for screen readers.
- 2026-10-11: Stage 14. The first session of a slot still asks for a starting load, once. Until that is answered the slot has no circles, so "sets plus one tap" holds from the first session only if starting loads are already set.
- 2026-10-11: Stage 15. The config file is strict: an unknown key or a value of the wrong type stops the api at start, naming the key. A key left out takes its default. `OTS_HOST` and `OTS_LOG_DIR` stay environment-only because the brief lists four settings for the file.
- 2026-10-11: Stage 15. While `OTS_DATA_DIR` is set, moving the folder from Settings is refused: the override would win at the next start and the move would silently not take.
- 2026-10-11: Stage 15. A move is refused if the target already holds an `ots.db`, is the current folder or inside or around it, is inside the repo, or is a network path. "Writable" is tested by writing a file. If a later step fails, the copy made in the target is removed so the same folder can be tried again; nothing in the old folder is ever removed.
- 2026-10-11: Stage 15. `POST /admin/restart` exits with code 0 only when the api runs from its built files; from source (`pnpm dev`, tests) it answers 409 and Settings says to restart by hand. A clean exit is not a failure to Task Scheduler, so the api task now runs the api in a loop, and the systemd unit uses `Restart=always`.
- 2026-10-11: Stage 15. `db:migrate`, `db:vacuum` and `restore.ps1` resolve the data folder the way the api does (environment, then config file, then default), so they follow a moved folder.
- 2026-10-11: Stage 15. Settings sections are cards with a button for a title, not `details` elements, and a closed section draws nothing. Raw buttons across Settings, the kit editor, setup, the exercise library and the timer became the Button primitive. Text and number inputs stay as they are: there is no input primitive.
- 2026-10-11: Stage 15. About reads version, licence and repository from the root `package.json`. "Copy diagnostics" falls back to showing the text to copy by hand, because the clipboard is not available to a page served over plain http on the LAN.
- 2026-10-12: Stage 16. The brief's acceptance says a new install's header shows no zeros, so a compliance part is left out while its count is zero ("Key sessions 0 of 3" is not shown), not only the streaks and run minutes. A week with nothing done has no line at all.
- 2026-10-12: Stage 16. Both streaks join the header line when they are above zero: "3 weeks in a row" and "4 mornings in a row". They only show on the current week. The streak queries now load before the page is drawn, so the header does not grow after first paint.
- 2026-10-12: Stage 16. The check-in folds 2.5 seconds after the last change to the weight, not at once, because plus and minus save on every tap. "Same today" folds at once. A card opened again by hand stays open until the page is left.
- 2026-10-12: Stage 16. The folded line lists the weight and the ticked habits by their labels, in lower case ("77.0 kg · protein shake").
- 2026-10-12: Stage 16. After a short timer finish the choice (planned or actual) leads to the usual finish form with that time shown, so RPE and notes can still be added; nothing is sent until Finish.
- 2026-10-12: Stage 16. A timer with no planned duration to offer skips the question and behaves as before.
- 2026-10-12: Stage 16. An undone session on an earlier day of the current week reads "to do" on its chip. Earlier weeks keep the plain chips, so an old week is not a wall of "to do".
- 2026-10-12: Stage 16. The overflow says "Log different time" where the primary button is Done or Start; where the primary button is already Log (run, ride, swim) it still says "Edit".
- 2026-10-12: Stage 16. The compliance grid treats any week with no planned sessions as empty, not only the weeks before the first plan. `GET /trends/weekly` gained `sessions_planned` for this.
- 2026-10-12: Stage 16. Switching the treadmill habit off is migration `0004_disable_treadmill_habit`. The stage 17 brief calls its own migration `0004`; it becomes `0005` because a migration cannot be changed once an install has run it.
- 2026-10-12: Stage 16. `/trends/daily` still returns sleep, energy and run RPE; only the chart is gone.
